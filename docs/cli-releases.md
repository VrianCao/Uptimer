# CLI releases

`uptimer-cli` is the only public npm package in this repository. Web, Worker, DB, and shared packages stay private. The CLI publishes compiled JavaScript, its README, changelog, and MIT license; consumers do not need TypeScript, pnpm, or a repository checkout.

## Release flow

1. Include a changeset in a CLI change: run `pnpm changeset`, select `uptimer-cli`, choose a semver increment, and describe the user-visible change.
2. Merge the change into `master` in `nexttylabs/Uptimer`. The Release CLI workflow creates or updates a release PR with package versions, changelog entries, and the updated pnpm lockfile.
3. Review and merge that PR. On the next `master` push, Changesets publishes unpublished versions to npm and creates package tags and GitHub Releases.

The initial packaging changeset bumps the existing `0.1.0` version to `0.1.1`. Subsequent changesets determine later versions. Changesets owns version/changelog updates; do not manually run the version command in the development worktree just to inspect it.

The workflow also supports manual retry on `master` after a transient publishing failure. It is serialized without cancelling an active publication. Release writes are restricted to the Main Repo and `master`, so forks and development branches cannot publish this package through this workflow.

## Maintainer setup

- Use an npm account permitted to publish `uptimer-cli`. This unscoped name does not require an npm organization. Public name availability does not reserve a name or establish publishing permission.
- In GitHub **Settings → Actions → General**, allow GitHub Actions to create pull requests.
- Configure the npm **Trusted Publisher** for `uptimer-cli` so this workflow publishes without a long-lived token:

  ```sh
  npm trust github uptimer-cli --file release.yml --repo nexttylabs/Uptimer --allow-publish
  ```

  The current configuration uses workflow `release.yml` in `nexttylabs/Uptimer` with publish permission. `npm trust list uptimer-cli` shows the active entry, and `npm trust revoke uptimer-cli --id=<id>` removes it.

- The release job grants `id-token: write` and runs pnpm 10.34.9 or newer, which exchanges that OIDC token for short-lived npm credentials. Provenance is attached automatically. No `NPM_TOKEN` secret is required; do not add one back, because a static token would bypass the trusted-publisher path.
- If branch protection requires CI on the generated release PR, set `RELEASE_GITHUB_TOKEN` to a GitHub App installation token or a suitably scoped fine-grained PAT with repository contents and pull-request write access. The default `GITHUB_TOKEN` can open the PR, but GitHub does not start ordinary push/pull_request workflows for events generated by that token. The release workflow itself re-runs CLI verification before any publish.

No GitHub permissions or secrets are created by this change. A newly created trusted publisher must complete its first successful publish within two days or it expires and must be recreated. A first publish performed outside this workflow (for example from a maintainer machine with a bypass-2FA token) does not weaken the trusted publisher; subsequent releases still authenticate through OIDC.

## Local verification

```sh
pnpm install --frozen-lockfile
pnpm changeset status
pnpm --filter uptimer-cli lint
pnpm --filter uptimer-cli typecheck
pnpm --filter uptimer-cli test
pnpm --filter uptimer-cli test:package
```

`test:package` builds the CLI, packs it, installs the actual tarball outside the repository using the already installed Zod dependency packed locally, and runs the installed `uptimer` executable. It makes no registry or application API calls and cleans up temporary files, including on failure. CI runs source and package tests on Node 22.14.0 and Node 24.

To produce a distributable tarball without publishing:

```sh
pnpm --dir apps/cli pack --pack-destination /tmp
```

`prepack` builds the distribution automatically. Install that tarball with `npm install --global /tmp/uptimer-cli-<version>.tgz`. Only the GitHub release workflow or an explicitly authorized maintainer operation should invoke `pnpm release`: it performs real npm publication, not a dry run. A local publish needs the maintainer's own npm 2FA code and works because the account allows token/OTP publishing; the workflow path needs neither.

## Agent skill

`skills/uptimer-cli/` is the single source for the agent skill. `prepack` copies it into the tarball as `skill/`, which is gitignored and rebuilt on every pack, so `uptimer skill install` works from an npm install. Users can also run `npx skills add nexttylabs/Uptimer --skill uptimer-cli` against the repository copy.

Edit `skills/uptimer-cli/` in the same change as the CLI behavior it documents, so the skill and the released executable cannot drift apart. A skill-only edit still needs a changeset, because the packaged copy ships inside the npm tarball.

## Tooling choice

`@changesets/cli` is a development-only dependency. It provides coordinated semver updates, changelogs, and publish detection for the existing pnpm workspace, and its official action manages the release PR and GitHub Release. Hand-written scripts would duplicate that release state and retry logic; ordinary npm version scripts do not provide the PR/changelog workflow. The dependency affects release tooling and the lockfile, not Worker/Web bundles or the CLI's runtime dependencies. CLI compilation reuses the existing TypeScript dependency; no bundler is added.
